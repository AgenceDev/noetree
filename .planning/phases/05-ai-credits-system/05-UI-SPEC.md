# Phase 5 — UI Design Contract

> Visual and interaction contract for the AI credits toolbar entry point, balance indicator, and zero-credit blocking dialog. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property          | Value                                                                                                                                                            |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tool              | shadcn (already initialized — `components.json` present, same instance as Phases 3/4, no re-init needed)                                                         |
| Preset            | `style: new-york`, `baseColor: neutral`, `cssVariables: true`, `prefix: ""` (source: `components.json`)                                                          |
| Component library | Radix UI primitives (via shadcn) — `Dialog`, `Badge`, `Tooltip`, `Button`, `Separator` (all already installed at `components/ui/`, none new this phase)          |
| Icon library      | lucide-react ^1.17.0 (source: `package.json`) — new icon this phase: `Sparkles` (represents the AI action + credit balance consistently, no other icon variants) |
| Font              | Geist Sans (`--font-geist-sans`), body + headings (source: `app/[locale]/layout.tsx`)                                                                            |

**No new shadcn components installed this phase.** `components/ui/dialog.tsx`, `components/ui/badge.tsx`, `components/ui/tooltip.tsx`, `components/ui/button.tsx`, `components/ui/separator.tsx` all already exist and are reused verbatim.

**New components this phase:**

1. `AiActionButton` (or equivalent name) — a `ToolbarButton` (existing pattern in `components/editor/EditorToolbar.tsx`) using the `Sparkles` icon, appended as a new toolbar group after the Link/Image buttons, separated by the existing `Separator orientation="vertical"` convention.
2. `CreditsBalanceBadge` — a `Badge` (`variant="secondary"`) wrapped in the existing `Tooltip` pattern, placed immediately to the right of the `AiActionButton` inside the same toolbar group. Reads balance reactively via `useQuery` (Convex, per established Phase 3 D-09 pattern — no polling).
3. `CreditsExhaustedDialog` (or equivalent name) — clones the `UpgradeModal.tsx` structure (D-08) with a **branching CTA** (D-11): Free users see the Phase 4 "Upgrade to Pro" CTA; Pro users at zero balance see a "Buy 50 credits" CTA that invokes the new top-up Server Action.

## Typography

Reuses the exact 3-size, 2-weight scale already declared and approved in Phase 3/4 (`03-UI-SPEC.md`/`04-UI-SPEC.md`) — no new sizes introduced by this phase's dialog or toolbar text:

| Role    | Size               | Weight         | Line Height |
| ------- | ------------------ | -------------- | ----------- |
| Body    | 16px (`text-base`) | 400 (regular)  | 1.5         |
| Label   | 14px (`text-sm`)   | 400 (regular)  | 1.5         |
| Heading | 20px (`text-xl`)   | 600 (semibold) | 1.2         |
| Display | 32px (`text-3xl`)  | 600 (semibold) | 1.2         |

Usage mapping:

- **Heading** — `DialogTitle` ("You're out of AI credits").
- **Body** — `DialogDescription` (branches per D-11, see Copywriting Contract).
- **Label** — not used in the dialog (no form fields).
- **Display** — not used this phase.

Exception: `CreditsBalanceBadge` inherits the shadcn `Badge` component's **built-in** `text-xs` (12px) / `font-medium` (500) styling unmodified — same rationale as Phase 4 not overriding `DialogTitle`/`DialogDescription` defaults. This is the existing installed primitive's default, not a new size/weight introduced by this phase's contract. Do not add a `className` font-size override to the badge.

## Color

60/30/10 split, reusing existing theme tokens (`app/globals.css`) — no new colors introduced, identical palette to Phase 3/4:

| Role            | Value                                                                                        | Usage                                                                                                                                                                                                                                                                                                                                                                            |
| --------------- | -------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Dominant (60%)  | `--background`                                                                               | The editor page/app shell behind the toolbar and dialog overlay (unchanged)                                                                                                                                                                                                                                                                                                      |
| Secondary (30%) | `--card` / `--secondary` (via `DialogContent`, toolbar surface, `Badge variant="secondary"`) | The dialog panel and the `CreditsBalanceBadge` background — the badge is **always neutral** (`secondary`), never color-coded by balance level (no red-at-zero state; the blocking dialog itself communicates zero balance, not badge color)                                                                                                                                      |
| Accent (10%)    | `--primary` (#7e10b2)                                                                        | Reserved for: (1) the `CreditsExhaustedDialog`'s primary CTA button fill ("Upgrade to Pro" or "Buy 50 credits"), (2) nothing else — the toolbar `AiActionButton` itself uses the existing neutral `ghost`/`secondary` `ToolbarButton` variants (same as Link/Image buttons), never primary-colored, so the toolbar doesn't visually imply "premium feature" before the user acts |
| Destructive     | `--destructive`                                                                              | Not used — no destructive action exists in this phase's UI (per CONTEXT.md specifics: no destructive-action copy needed). Zero-balance is a **blocked/neutral** state, not an error state — do not tint the badge or button with `--destructive`                                                                                                                                 |

Accent reserved for: the `CreditsExhaustedDialog`'s single primary CTA button only (branches text but stays the `default` Button variant in both branches). The dismiss button ("Maybe later") uses the existing `secondary` Button variant, matching `UpgradeModal`'s convention exactly.

## Copywriting Contract

New i18n namespace `AiCredits` (next-intl, flat-namespace convention matching `PlanEnforcement`/`Pricing`), added to `messages/en.json` and `messages/fr.json`:

| Element                                | Copy (en)                                                                                                                                                                                                                                                          |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Toolbar button tooltip                 | "AI action (1 credit)" — appended to `Editor.tooltips` namespace, matching the existing `link`/`image` tooltip convention                                                                                                                                          |
| Balance badge tooltip                  | "{n} AI credits remaining" (pluralization via next-intl ICU, e.g. "1 AI credit remaining" / "0 AI credits remaining")                                                                                                                                              |
| Dialog title (both branches)           | "You're out of AI credits"                                                                                                                                                                                                                                         |
| Dialog body — Free user (D-10/D-11)    | "Free plans don't include AI credits. Upgrade to Pro for 100 AI credits a month, with the option to top up anytime."                                                                                                                                               |
| Dialog body — Pro user at 0 (D-11)     | "You've used all your AI credits for this cycle. Buy 50 more credits for 2€, or wait for your next billing cycle to reset."                                                                                                                                        |
| Primary CTA — Free branch              | "Upgrade to Pro" — routes to `/pricing` (same label/target as Phase 4's `UpgradeModal`, for consistency)                                                                                                                                                           |
| Primary CTA — Pro branch (D-12)        | "Buy 50 credits" — invokes the new top-up Server Action, opening Stripe Checkout in `payment` mode                                                                                                                                                                 |
| Secondary/dismiss action (both)        | "Maybe later" (closes the dialog, no navigation — identical convention to `UpgradeModal`)                                                                                                                                                                          |
| Empty state                            | Not applicable — no list/empty-state UI this phase; the zero-balance dialog above is the equivalent "nothing left" state                                                                                                                                           |
| Success feedback (AI action completes) | None beyond the reactive balance badge decrementing in place (Convex `useQuery`, D-13-adjacent pattern) — no toast/snackbar library exists in this codebase; do not introduce one for a 1-credit deduction                                                         |
| Error state (refund path, D-06)        | Not applicable this phase — the placeholder action always succeeds (D-01), so the refund path is implemented server-side but has no reachable UI state to design. When the real AI capability is built, its failure/error copy will be scoped in that future phase |
| Destructive confirmation               | Not applicable — no destructive action in this phase's UI (per CONTEXT.md specifics; the AI action and top-up purchase are both non-destructive, additive operations)                                                                                              |

Distinguishing the zero-credit block from a generic mutation failure (needed so the client opens `CreditsExhaustedDialog` instead of silently failing), following the exact `NOTE_LIMIT_REACHED` convention from Phase 4 (`04-CONTEXT.md` D-07/`04-UI-SPEC.md`): the `deductCredit` mutation should throw a distinguishable message, e.g. `throw new Error("INSUFFICIENT_CREDITS")`, and the toolbar action's `onClick`/`onError` handler checks for it before opening the dialog. (Implementation detail for planner/executor — copy contract above is what the checker validates.)
