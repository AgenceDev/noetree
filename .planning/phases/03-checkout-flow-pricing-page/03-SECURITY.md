## Trust Boundaries

| Boundary                                                   | Description                                                                                                               | Data Crossing                                       |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| npm registry → local build                                 | Third-party package source (jsdom, shadcn badge) crosses into the build                                                   | Package source code                                 |
| client → Server Action (`createCheckoutSession`)           | Untrusted pricing-page client invokes the Server Action; only `locale` crosses as an explicit input                       | `locale` string; thrown error messages cross back   |
| Server Action → Stripe API                                 | Server-side call holding `STRIPE_SECRET_KEY`, writes `clerkUserId` into Stripe metadata                                   | Price ID, customer ID, clerkUserId, redirect URLs   |
| client → success page display                              | Client renders subscription status but cannot write it; entitlement source is Convex, written only by the Phase 2 webhook | `status` read-only, via reactive query              |
| Stripe hosted checkout → app webhook → Convex              | Payment confirmation crosses from Stripe into the app's webhook, the sole writer of subscription state                    | Signed Stripe event payload                         |
| authenticated `(app)` routes ↔ public `(marketing)` routes | Route-group split defines which pages render inside the authenticated app shell vs. the public chrome-free shell          | Rendered UI chrome (AppSidebar/Header)              |
| Convex `getSubscription` query ↔ caller identity           | Convex's own auth boundary — the query derives the caller's identity from the Convex session, not from any argument       | `clerkUserId` (server-derived only, post CR-01 fix) |

## Informational Findings (non-blocking)

- **Unregistered attack surface, found and fixed, not logged as a Threat Flag:** A cross-user IDOR (`api.subscriptions.getSubscription` accepted an arbitrary `clerkUserId` argument with no ownership check, allowing one signed-in user to read another user's billing status) was found and fixed under `03-REVIEW.md` CR-01 (commit `e5793d5`, 2026-07-09) — the query now derives identity exclusively from `ctx.auth.getUserIdentity()`. This is a genuine security fix and is fully verified in the current codebase (`convex/subscriptions.ts:4-17`), but it was never logged under any of the 7 plans' `## Threat Flags` sections (03-02-SUMMARY.md, the only plan with that section, states "None"). Recommendation: future phases should log fixes discovered via ad hoc code review (`03-REVIEW.md`-style) as `## Threat Flags` in the relevant plan's SUMMARY, not only in a separate review doc, so security audits don't have to cross-reference review artifacts outside `<required_reading>` to find them.
