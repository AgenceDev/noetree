<objective>
Decompose the root `app/[locale]/layout.tsx` so the authenticated app-shell chrome (HeaderProvider, SidebarProvider, AppSidebar, SidebarInset, Header) lives in a NEW `(app)` route group that wraps only the existing authenticated routes, and the root layout retains only the truly global providers. This is the architectural precondition that makes a chrome-free `(marketing)` shell actually achievable at runtime.

Why this plan exists: In the Next.js App Router a nested layout composes INSIDE its ancestor layout — a route group cannot remove chrome an ancestor already rendered. The original approach (adding `(marketing)/layout.tsx` under an unchanged root that unconditionally renders AppSidebar/Header) would still render the sidebar/header around /pricing and /checkout/success. Route groups affect URL grouping, not layout inheritance. The only correct fix is to pull the app shell OUT of the root and into a sibling `(app)` group, leaving the root chrome-free so `(marketing)` can render clean.

Purpose: Deliver D-01/D-04 (no app-shell chrome on marketing routes) as a genuine runtime guarantee, not a false-green grep.
Output: A stripped root layout, a new `(app)` route group with the app shell and the three moved authenticated routes, and the chrome-free `(marketing)` shell.
</objective>
