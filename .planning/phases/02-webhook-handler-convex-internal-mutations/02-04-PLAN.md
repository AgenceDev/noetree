<threat_model>

## Trust Boundaries

| Boundary                              | Description                                                                                                                                                 |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Next.js route -> Convex public action | `processWebhookEvent` is reachable by ANY client holding `NEXT_PUBLIC_CONVEX_URL`, not only the Next.js route — the shared-secret check is the only barrier |
| Convex action -> internalMutations    | `ctx.runMutation(internal.*)` calls are internal-only, not reachable from any public client SDK                                                             |

## STRIDE Threat Register

| Threat ID | Category               | Component                                                               | Disposition | Mitigation Plan                                                                                                                                                                                                                                                                                                          |
| --------- | ---------------------- | ----------------------------------------------------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| T-02-02   | Elevation of Privilege | Direct client call to `processWebhookEvent` bypassing the Next.js route | mitigate    | `args.secret !== process.env.INTERNAL_WEBHOOK_SECRET` check as the handler's first statement, throwing before any dispatch or mutation call                                                                                                                                                                              |
| T-02-03   | Information Disclosure | Timing side-channel on the `!==` shared-secret comparison               | accept      | Per RESEARCH.md Assumption A1 — this is a defense-in-depth secondary check behind Stripe's own signature verification (Plan 02-05) and HTTPS transport; a practical timing attack would require many precisely-timed requests to a serverless backend, low practicality. No `crypto.timingSafeEqual` used in this phase. |
| T-02-04   | Tampering (replay)     | Duplicate delivery of any of the 5 event types                          | mitigate    | Dispatch always defers the idempotency check-and-mark to the target `internalMutation` (Plans 02-02/02-03) — the action itself never checks or writes `processedStripeEvents` directly, avoiding the two-call race Convex docs warn against                                                                              |

</threat_model>
