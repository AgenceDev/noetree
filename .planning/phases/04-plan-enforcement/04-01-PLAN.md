<objective>
Enforce the Free tier's 20-note cap server-side inside the `createNote` Convex mutation, so a Free user cannot exceed 20 total notes regardless of client state, while Pro users (subscription `status === "active"`) create unlimited notes.

Purpose: This is the security-critical core of the phase — the limit MUST hold even when the client bypasses UI checks (ROADMAP SC1). It also establishes the `NOTE_LIMIT_REACHED` error contract that the frontend (plans 02/03) keys its upgrade modal off of.

Output: A new `isProUser` helper, a limit gate in `createNote`, and a `convex/notes.test.ts` proving SC1/SC2/SC3 plus the past_due/canceled → Free cases.
</objective>

<threat_model>

## Trust Boundaries

| Boundary                                        | Description                                                                                                                              |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| client → Convex createNote mutation             | Untrusted client input (note args) and untrusted client-side plan state cross into the server. The client may bypass any UI limit check. |
| createNote → subscriptions table (via identity) | Plan/tier authority must derive from the authenticated identity, never from client-supplied data.                                        |

## STRIDE Threat Register

| Threat ID | Category               | Component                     | Disposition | Mitigation Plan                                                                                                                                                     |
| --------- | ---------------------- | ----------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-04-01   | Elevation of Privilege | createNote note-limit gate    | mitigate    | Enforce the 20-note cap in the Convex mutation itself (Task 2), so a client that bypasses UI cannot exceed 20 (ROADMAP SC1). Covered by test Task 3.                |
| T-04-02   | Spoofing / IDOR        | isProUser plan resolution     | mitigate    | Resolve Pro status exclusively from `ctx.auth.getUserIdentity().subject` (Task 1), never a client-supplied plan/status argument — mirrors 03-REVIEW.md CR-01 fix.   |
| T-04-03   | Denial of Service      | count query on notes by owner | accept      | `.take(FREE_NOTE_LIMIT + 1)` bounds the scan to O(21) rows regardless of total notes owned (guidelines rule), so the check cannot be turned into an unbounded scan. |
