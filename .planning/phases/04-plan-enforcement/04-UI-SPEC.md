Lift the `open` state to a shared location (e.g. a small hook or context) so both call sites can trigger the same dialog instance, rather than duplicating the JSX in two files.

| 2xl   | 48px  | Not used this phase                                                |

## Typography

Reuses the exact 3-size, 2-weight scale already declared and approved in Phase 3 (`03-UI-SPEC.md`) — no Display size needed since this dialog has no hero text:

| Role    | Size               | Weight         | Line Height |
| ------- | ------------------ | -------------- | ----------- |
| Body    | 16px (`text-base`) | 400 (regular)  | 1.5         |
| Label   | 14px (`text-sm`)   | 400 (regular)  | 1.5         |
| Heading | 20px (`text-xl`)   | 600 (semibold) | 1.2         |
| Display | 32px (`text-3xl`)  | 600 (semibold) | 1.2         |

Usage mapping:

- **Heading** — `DialogTitle` ("You've reached the Free plan limit").
- **Body** — `DialogDescription` (limit explanation + what Pro unlocks).
- **Label** — not needed in this dialog (no form fields, no fine print).
- **Display** — not used this phase.

No third weight — semibold (600) for the title only, regular (400) for the description, matching `components/ui/dialog.tsx`'s built-in `DialogTitle`/`DialogDescription` defaults (do not override with inline font classes).

## Color

60/30/10 split, reusing existing theme tokens (`app/globals.css`) — no new colors introduced, identical palette to Phase 3:

| Role            | Value                                                         | Usage                                                                                                                                                                                                                                                           |
| --------------- | ------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Dominant (60%)  | `--background`                                                | The app shell behind the dialog overlay (unchanged — dialog is an overlay, not a page)                                                                                                                                                                          |
| Secondary (30%) | `--card` + `--border` (via `DialogContent`'s default surface) | The dialog panel itself (`components/ui/dialog.tsx` `DialogContent` already applies `bg-background border` — no override)                                                                                                                                       |
| Accent (10%)    | `--primary` (#7e10b2)                                         | Reserved for: (1) the "Upgrade to Pro" button fill (primary `Button` variant, default), (2) the inline link/button target styling if a lock/crown icon is added next to the title (optional, lucide `Crown` or `Lock`, sized `h-5 w-5`, colored `text-primary`) |
| Destructive     | `--destructive`                                               | Not used — this dialog has no destructive action (dismissing/"Maybe later" is a neutral `secondary` button, not destructive)                                                                                                                                    |

Accent reserved for: "Upgrade to Pro" button only (and its optional adjacent icon). The "Maybe later" / dismiss button uses the existing `secondary` Button variant (`--secondary`/`--secondary-foreground`), same convention as every other dialog's cancel button in this codebase (rename dialog's "Cancel", new-note dialog's "Close").

## Copywriting Contract

New i18n namespace `PlanEnforcement` (next-intl, flat-namespace convention matching `Pricing`/`CheckoutSuccess`/`Notes`), added to `messages/en.json` and `messages/fr.json`:

| Element                          | Copy (en)                                                                                                                                                                                                                                                                  |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Dialog title                     | "You've reached the Free plan limit"                                                                                                                                                                                                                                       |
| Dialog body                      | "Free plans include up to 20 notes. Upgrade to Pro for unlimited notes and 100 AI credits a month."                                                                                                                                                                        |
| Primary CTA                      | "Upgrade to Pro" — routes to `/pricing` (D-06), same label used on the Pricing page for consistency                                                                                                                                                                        |
| Secondary/dismiss action         | "Maybe later" (closes the dialog, no navigation — matches the app's existing "Close"/"Cancel" dismiss convention but uses a softer, upgrade-specific phrase since this is a soft paywall, not a form cancel)                                                               |
| Empty state                      | Not applicable — this phase has no list/empty-state UI, only the limit-triggered modal                                                                                                                                                                                     |
| Error state (generic, non-limit) | Existing behavior unchanged: other `createNote` failures (e.g. network error) keep the current silent revert-only `onError` behavior — this phase does not add general error surfacing, only the specific limit-reached case (per D-07, keyed off a distinguishable error) |
| Destructive confirmation         | Not applicable — no destructive action in this phase's UI (dismissing the upgrade modal is non-destructive)                                                                                                                                                                |

Distinguishing the limit error from other `createNote` errors (needed so the client can decide to open this dialog instead of silently reverting): the mutation should throw a distinguishable message, e.g. `throw new Error("NOTE_LIMIT_REACHED")`, and the two `onError` handlers (`hooks/useNoteMutations.ts` and the root-page mutation in `app/[locale]/(app)/notes/page.tsx`) check `err.message === "NOTE_LIMIT_REACHED"` before opening the dialog, falling through to the existing silent-revert behavior for any other error. (Implementation detail for planner/executor — copy contract above is what the checker validates.)
