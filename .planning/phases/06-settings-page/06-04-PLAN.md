<pitfall_reminders>

- Seconds-vs-ms (Pitfall 1, MUST apply): subscription.currentPeriodEnd is stored in Unix SECONDS. Always construct the Date as new Date(currentPeriodEnd \* 1000). Rendering it raw produces a January-1970 date. Both the "Renews on [date]" and "Cancels on [date]" lines and the cancel-confirmation description use this. NOTE: creditTransactions.createdAt is already MILLISECONDS (Date.now()) — do NOT multiply those by 1000.
- Date formatting: use toLocaleDateString(locale, { year: "numeric", month: "long", day: "numeric" }), locale-aware via the active next-intl locale. No date library is installed — do not add one.
- No redirect confusion: the cancel/resume Server Actions do not redirect; on success just let useQuery re-render reactively. Wrap the awaited action call in local isPending/error state.
- UI conditional rendering is NOT security. The Plan 02 actions already re-verify server-side; the UI conditionals here are UX only.
  </pitfall_reminders>
